# Pooya Labs — Portfolio quality plan

This plan applies only to the personal profile repository. It does not authorize edits to any project repository.

## Objective

Make the profile a credible, bilingual engineering portfolio. Prioritize evidence and clarity over decoration.

## Portfolio standards

- [x] Establish a restrained visual identity and reusable brand assets.
- [x] Write a bilingual profile introduction.
- [x] Link the current project repositories and social profiles.
- [x] Document the brand voice, palette, and visual rules.
- [x] Add a reusable project case-study standard.
- [ ] Verify each project's actual current status before describing it as active, beta, or stable.
- [ ] Select 3–4 strongest projects for primary emphasis; keep the rest in an additional-work section.
- [ ] Add genuine screenshots or working demos where available.
- [ ] Add concise technical case studies with verified architecture and test evidence.
- [ ] Review profile accessibility: heading order, descriptive links, image alt text, and bilingual readability.
- [ ] Review profile pinned repositories with the owner; do not change pins without explicit approval.
- [ ] Add a personal domain when one is available.

## Change-control boundary

All work in this plan is limited to `pooya-labs/pooya-labs`.

Do not modify, branch, merge, rebase, or change settings in:
- `orbit`
- `aetherflow`
- `globalcart`
- Any other project repository

Project-specific facts may be included only after they have been verified from information supplied by the project owner or a confirmed read-only review. A README description is not proof that every listed capability is complete.

## Current state

The profile README, header SVG, monogram SVG, and brand-system document are present in this repository. The next high-value step is verified project evidence—not more decorative graphics.
